# Mobile Adaptation Implementation Plan

**Goal:** 让手机竖屏、横屏能完整观察天体、操作时间、阅读课程与日历，同时保留桌面布局及交互。

**Architecture:** 在共用 `mobile.css` / `mobile.js` 中集中维护手机布局；以小屏幕和手机横屏媒体查询启用。地球与太阳系仅增加读取可用画面区域的接口，桌面沿用原有计算；不修改天文模型、语音和后台课程数据。

**Tech Stack:** 原生 HTML/CSS/JavaScript、Canvas/Three.js、Playwright（Chromium / WebKit）、Node。

## 方案取舍

1. 单纯压小字体和按钮无法解决遮挡与误触。
2. 采用手机控制区折叠、讲解面板可展开/缩小、卡片摘要可展开、独立弹层滚动；保持现有深色与青金配色。
3. 独立开发手机版会重复维护页面和课程逻辑，本次不采用。

## 实施步骤

### 1. 建立基线
- 文件：`.deploy-check/v412-harness.cjs`、`v412-baseline.cjs`（本地验证工具）。
- 使用现有真实课程和已生成音频副本；记录 1440×900、1024×768 桌面，以及 390×844、320×568、844×390 手机截图与控件几何。
- 本地验证数据位于 `.deploy-check/v412-data`，不写服务器维护内容。

### 2. 手机操作区与弹层
- 新增 `mobile.css`、`mobile.js`，在 `index.html`、`solar-system.html` 加载。
- 日期独立一行；常用时间控制保留，其他工具收进「更多」。控件保持原节点与事件，切回桌面恢复原顺序。
- 增加安全区、动态可见高度、至少 44px 的主要触摸目标；日历/图层/时区/速度弹层支持滚动和明确关闭。

### 3. 讲解和信息卡
- 在共享脚本中为手机增加展开讲解、缩小看画面；问题与日期选择自动提供较大空间。
- `card-layout.js` 对手机走新的布局，桌面原逻辑保留；摘要卡点击展开，完整内容可滚动。
- 横屏讲解放右侧；竖屏放在控制栏上方。关闭、暂停、跳过、课程切换都必须可点击。

### 4. 画面与手势
- `index.html` 的地球中心和半径从手机可用区域计算；太阳系 `focusCourse` 使用同一区域，缩放只移动镜头。
- 布局变化不得使用户的手势失效；旋转、双指缩放/平移、上帝之手拖动，以及日期确认继续工作。
- 浏览器地址栏/键盘和方向切换触发合并更新，避免每帧查询 DOM。

### 5. 辅助页面
- `admin.html` 小屏表单、课程工具栏、输入字号及弹窗适配。
- 检查开场选择、加载页和引导卡在横屏/短屏中的可见性。

### 6. 验证与发布
- 桌面控件几何与基线对比；手机点击、滚动、日期确认、课程展开缩小、卡片、图层互斥及旋转方向切换验证。
- 真实触摸事件验证太阳系缩放/平移和上帝之手、地球缩放；检查滚动面板不带动背景。
- 覆盖 Chromium 手机、WebKit 手机（可用时）、平板和桌面，检查控制台错误。
- 本次发布 4.1.2 至测试环境，备份与保留正式环境独立数据；通过验证后交付测试链接。
