# 4.0.17：开场地图拼接痕迹与手机卡顿

## 确认的问题

- 截图的明暗方格在 `satellite-8000.jpg` 原文件及 4.0.16 成片 8.95 秒处可以复现，是原卫星影像的拼接边界。
- 4.0.16 手机和桌面共同加载 720p/60 fps，约 5.47 MB、平均 2.78 Mbps，编码为 H.264 High 3.2、全范围像素。需要降低手机网络与解码负担，并实测缓冲和掉帧，不能仅用截图判断流畅度。

## 修复

- 区域和全国阶段换成同一 NASA Blue Marble 数据，记录 EPSG:4326 经纬度范围，保证位置和过渡一致。
- 15 秒镜头保持原有路径；移动端和低速网络使用 540p/30 fps 的轻量版本，电脑保留 720p/60 fps，统一为兼容的有限范围 YUV420P。
- 避免在前 12 秒逐帧修改相同 CSS 缩放值，保留最后的地球尺寸衔接。
- 地球主界面同分辨率 WebP 将北极贴图从 6.69 MB 降至 0.89 MB；加载失败仍回退 PNG。开场视频缓存足够后才下载被覆盖的地球、月亮图片，跳过时立即释放。
- 地球页面的 Three.js 只在进入星空旅行时加载，减少开场争抢带宽。视图请求有取消检查，避免加载完成后覆盖用户的新选择。
- 太阳系页面移除约 0.98 MB 内嵌 Base64 贴图，改用已有的同一批图片文件，逐个核对解码后字节完全相同；页面约 105 KB。开场期间不加载或初始化三维场景，跳过或普通访问时再加载，提供加载提示。
- 连续检查全国段，测试 1.6 Mbps、CPU 四倍减速条件下的完整播放与音频、跳过、重播、片尾切换。
- 发布测试环境，更新高清下载成片。

## 本地验证

- 4.0.16 对照：首次播放约 2.92 秒，播放后 5 次缓冲约 40.5 秒，15 秒视频到 58.2 秒才结束，900 帧中丢 7 帧。
- 4.0.17 同条件（393×850、DPR 2、触摸、1.6 Mbps、100 ms 延迟、CPU 四倍减速、空缓存）：1.57 秒开始播放，16.65 秒自然结束；播放期间 0 次缓冲、450 帧中丢 0 帧。地球贴图 15.58 秒下载完成，早于片尾。
- 太阳系入口同条件：1.57 秒开始播放，16.66 秒自然结束；播放期间 0 次缓冲、450 帧中丢 0 帧。视频期间未下载或初始化 Three.js 和行星贴图。
- 手机视频 1,747,307 字节，电脑视频 4,440,797 字节；均为 15.000 秒，YUV420P/BT.709、H.264/AAC。
- 9.2 秒的实际手机压缩成片已检查，全国阶段不再出现原影像的明暗拼接条带。
- 电脑太阳系与手机地球入口的音频、自动播放受限后的点击开启声音、片尾尺寸、自然结束、重播、跳过、会话内不重复开场均通过。
- 已验证 WebP 失败回退、南极 WebP、按需加载星空旅行及返回地球；太阳系跳过开场和普通访问时，行星贴图与三维场景均正常加载。

以上是浏览器模拟测试，尚未在用户截图中的手机上实测。
