# Unified Earth / Solar View Implementation Plan

**Goal:** 在同一文档中切换地球与太阳系，保留时间、课程、音频缓存和手机操作，切换不再触发开场或 5 秒加载页。

**Architecture:** 一个 HTML 入口、一套课程/开场/移动端工具。两个视图工厂拥有自己的 DOM、场景和控件；只有当前视图接入文档并运行绘制。路由器传递时间状态并维护浏览器历史。

**Tech Stack:** 原生 JavaScript 工厂、HTML template、Canvas 2D、Three.js、History API、现有 CacheStorage。

## 架构决策

- 采用独立视图模块 + 单页面路由。相比完全重写同一套控件，能保留两种视图特有的时区、图层和手势功能，降低天文算法回归风险。相比 iframe，不需要第二套课程、音频或文档加载。
- 未显示视图的 DOM 保留在离线根节点中，避免重复 ID 和隐藏控件被全局查询命中。视图查询及全局事件通过作用域接口绑定；日历增加可选查询作用域。
- 太阳系首次使用时创建 WebGL，之后复用相机和图层状态；离开时取消动画与手势。资源文件仍在首次加载缓存，不预先同时运行两个渲染器。
- 共享的绝对时间、播放状态和时间倍率在切换时交接；绘制时钟恢复时重置，避免停留另一视图后时间突然跳变。
- 课程内切换通过同一路由异步完成，讲解面板、音频元素、段落记录不重建。手动切换暂停讲解，恢复时回到课程所属视图。
- 旧 `solar-system.html` / `index.html` 地址继续可用。以 `view=solar/earth` 表示场景，后退/前进只切场景，保留预览等查询参数。

## 实施顺序

1. 从现有 HTML 提取 `earth-view.js/css`、`solar-view.js/css` 和模板；保持算法与绘图参数。
2. 新建 `views.js`：作用域、初始化、切换、状态传递、历史、异常提示和最新切换请求优先。
3. 调整 `assistant.js`、`mobile.js`、`calendar-events.js`、卡片布局和统一预加载入口。
4. 调整 server 旧链接路由、Dockerfile、SW 及版本到 4.2.0。
5. 浏览器检查：单文档往返、共享日期/暂停/倍率、相机状态、课程跨章节/返回今天、手动暂停、日历确认、手机触控、阴阳历、旧 URL、浏览器历史、无重复 ID、隐藏视图不绘制。
6. 先部署测试环境并保留正式 4.1.6，供用户确认此次较大交互调整；保留各自后台课程和数据。

## 风险与验证

- 异步首次切换可与连续点击竞争：请求编号保证最后一次选择生效，失败保留原画面并允许重试。
- 手机控件会搬动节点：切换前还原旧工具栏，切换后重绑定新工具栏，讲解面板保留。
- iPhone 内存：不重复加载音频、不重建视频、不同时运行两个绘制循环；WebKit 模拟无法替代真实 iPhone 的 GPU 压力验证。
- 正式发布前需在测试地址检查实际讲课体验；自动化验证覆盖可客观检查的状态与交互。
